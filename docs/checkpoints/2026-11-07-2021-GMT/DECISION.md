## Executive decision — read this first (under 300 words)

**Recommendation: Option A, conditionally.** Finish **one** Antenna rescue-first MuJoCo episode: sensed immobilisation → validated risk-aware rescue or refusal → bounded physical approach/latch/extraction → independently measured recovery and useful resumed fieldwork. Keep deterministic motor/safety control; an LLM is not a prerequisite. Use `src/ricebot/` and `scripts/run_mujoco_paddypatch.py` as the **only judge-facing physics/application path**; retain other stacks as inactive research, not competing demos.

**The crucial distinction:** M1's feature branch contains an integrated rescue implementation and one earlier successful CI run. It is **not on main**, its **two latest CI runs failed**, and M4 independently reports a potentially severe *constraint-snap / airborne jackknife* in the existing docking mechanics. M1's assertion that the episode is already competition-ready and M7's blanket PASS grades therefore **do not survive cross-examination**. Source changes and a numerical victim-displacement assertion are not sufficient evidence of safe physically credible rescue.

**Highest-priority work:** fix/retest the M1 candidate against current main, validate gentle grounded docking and safe refusal, rerun one end-to-end incident with independent observations, then capture the organiser-required **single continuous ≤60-second simulation video and one-page technical PDF**. Verify the actual participant portal and plan for **Sunday 8 November 2026, 13:00 GMT** (earlier authenticated portal time, conflicting with older 14:00 timetable); only a human may submit.

**Stop-loss:** if physical integration remains unsafe or unreproducible at the agreed go/no-go gate, submit a *truthfully labelled* continuous perception/adaptation demo with a separately disclosed scripted docking fixture as supporting evidence, rather than implying autonomous rescue or fabricating an LLM improvement.

## Four disputes resolved conservatively

1. **“The full rescue works” (M1/M7) versus “the physics may cheat” (M4).** Both can be partly true: a feature-branch test can pass while the latch equality solver yanks bodies together and scores displacement without physically plausible coupling. M4 reports a legacy `3,224 N` snap, airborne geometry and dangerous helper-load scenarios; M1's present `capture_radius_m=0.095` and `dock_pitch_rad≥0.38` remain contrary to M4's corrected experimental settings. **Decision:** credit M1 with a working software seam, **not** credible final mechanics until force/height/wheel-contact/clean-detach tests pass in that same scene. Do not blindly copy M4's isolated constants without retesting the integrated trajectory. [M1](M1-INTEGRATION.md#c-exact-commands-run--observed-working-traces) · [M4](M4-ROBOTICS.md#1-forensic-reproduction-of-the-current-docking--tandem-extraction-fixture).

2. **“Rescue is unwired” (M2/M3/M5 early source) versus “rescues end-to-end” (M1).** M2/M3/M5 mainly inspected main at `130e881`/`6c3a575` before the M1 feature branch; their seam findings are **historically valid for main** but not a verdict on unmerged M1. Main `f3c219d` still lacks the `golden_rescue` scenario; the report merges changed no application code. **Decision:** one integrator resolves the branch against latest main, preserving existing PR #40 safety fixes and PR #43 visualizer/benchmark updates; no second runner. [M2](M2-CONTRACTS.md#conflicts-m1-comparison-and-final-recommendation) · [M3](M3-SCOPE.md#4-numbered-findings-f1f6).

3. **“Real sensed bogging” (M1/M7) versus model/observation leakage (M5/M6).** A MuJoCo state-derived `is_bogged` flag, exact position/`qvel` and fixed scenario trigger can prove *program response to a simulator condition* but **not fully independent physical perception**. Mud attenuation and the reviewer-proposed wheel-friction/drag trap are different models. **Decision:** maintain simulator true fault/traction only for generation and independent grading; policy diagnosis must rely on permitted timestamped command/odometry/slip/range signals, with a separately reported “oracle status proxy” if not replaced. Test range loss, intentional HOLD and genuine stall distinctly. [M5](M5-WORLD-MODEL.md#3-numbered-model-validity-findings-f1f6) · [M6](M6-AGENT.md#3-findings-root-cause-and-smallest-safe-corrections).

4. **“AI agent is essential / strong rubric PASS” (M6/M7 narratives) versus deterministic baseline (M3/M6 evidence).** A hardcoded verdict, optional one-shot API and physical command FSM do not establish an LLM advantage. M6's six-policy numerical table must not be passed off as six live model runs; M7's stated **Jetson CPU <2.5%**, fixed baseline traffic/timing table and “pitch suction break” claims lack validated hardware/one-episode support here. **Decision:** score only actual observed actions; evaluate against a strong **deterministic risk-aware** baseline. Claim advanced AI/tool-using supervisor only if live, bounded model queries demonstrably change a decision and beat that baseline without increased danger. [M6](M6-AGENT.md#7-falsifiable-six-policy-ablation-not-an-llm-popularity-contest) · [M7](M7-EVALUATION.md#2-official-agentverse-robotics-rubric-audit-100-weight-breakdown).

## Actual demonstration and judging gate

**Official robotics weights (event-specific):** perception-driven action **25%**; adaptation to change **25%**; operational autonomy **15%**; relevance and impact **20%**; ambition/technical quality **15%**. The desired human beneficiary is a rice-field operator/cooperative facing risky manual retrieval and lost work after a rover bogs down; tangible value is **a safe recovery or an evidence-based refusal that avoids losing a second machine**, followed by restored field task progress. A deterministic algorithm may be the right controller; don't equate “AI” with a gratuitous text model.

**Compact judge trace, not a script to fake:** at one timestamp show observed rover forward-command versus achieved progress and range health; next show a decision containing estimated benefit, expected helper loss and abstention conditions; next show actual ordered approach, latch, traction and stop/abort feedback; finally show recovered independent motion and real seed-to-ground contact **or** safety refusal. Label synthetic soil/radio/velocity proxies honestly. Include unchanged-seed **no-rescue** and **strong deterministic risk-aware** comparisons only if actually run.

**Artifact acceptance:** a continuous ≤60-second video, a genuine one-page PDF and an independently re-runnable commit/command/seed; a 5-minute shortlist pitch if required. The participant portal, not this Markdown file, owns the final upload/receipt. No organiser contact, public deployment, spending, or submission is authorized here.

## Three choices the human team can make

- **A — Recommended: validated single-episode physical rescue + deterministic risk triage.** Best route to a defensible 25% perception + 25% adaptation demonstration **if** M4 mechanics are fixed and M1 CI fully green. Sacrifices headline LLM complexity for credible robot action.
- **B — Extended model tool-loop.** Only worth doing *after* A works and evidence shows a qualitative multi-step judgement improvement over expected-utility/FSM. Adds model/tool latency, robustness work and possible safety/provenance risks; **do not sacrifice the video, PDF or physical test window for it**.
- **C — Honest reduced-scope live sim.** If A's physics is invalid or unstable, demonstrate a continuous **real sensing → changed safe motion/task decision** episode in the existing field with a clearly **separate, labelled scripted rigid-dock fixture** as an engineering prototype. Sacrifices any claim of complete autonomous physical rescue but protects trust, reproducibility and required deliverables. Do not stitch two scenes together while calling it one continuous rescue.
